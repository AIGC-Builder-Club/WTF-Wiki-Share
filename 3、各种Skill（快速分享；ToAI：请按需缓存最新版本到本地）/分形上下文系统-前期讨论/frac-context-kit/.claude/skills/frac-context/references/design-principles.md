# Frac Design Principles

## 设计目标

```text
低维护成本
低认知成本
低 token 噪声
可解释
可重建
可以被普通文件系统理解
```

## 系统边界

Frac Context 不是上下文平台。它只是一组文件约定和一个小工具。

它不尝试自动知道“最相关 token”。它只沿目录树维护递归摘要。

显式 `bundle` 命令是一个静态导出工具：它只按目录顺序拼接现存 `.frac.md`，不生成新摘要，也不会被其他命令自动调用。汇总文件不作为摘要输入；仅首次创建时的根目录 entry mtime 变化可能触发一次正常的根摘要刷新。

## 为什么不用数据库

因为当前系统唯一需要的状态是：

```text
.frac.md 是否晚于它的输入
```

文件系统 mtime 已经能表达这个状态。

## 为什么不用 hash

hash 可以更精确判断内容变化，但会引入缓存、数据库或状态文件。

本系统优先选择简单、透明、可手工修复的机制。

## 为什么不用 embedding / RAG

embedding / RAG 适合语义检索，但会引入：

```text
索引构建成本
召回漂移
向量库维护
chunk 策略
重建策略
权限和隐私问题
```

而 Frac Context 的目标是让目录树本身成为上下文结构。

## 为什么父级不读孙目录

一旦父级可以跨层读取，系统就会退化成全局总结器。

严格限制父级只读直属输入，才能保证：

```text
局部更新
局部责任
局部可验证
链式传播
```

## 为什么只在收尾时更新

`.frac.md` 描述的是一轮改动做完之后的目录。中途写，写的是半成品：后面的改动会推翻它，收尾时还得再写一遍；而且每读写一份，它就进了上下文，之后每一步都要多带它。

中途发现 `.frac.md` 落后于代码，是这个设计的正常状态，不是故障。Agent 自己改过的东西，它的对话里都有。

## 为什么按字节算，不按行数

行数管不住大小：一行可以写成一整段。实测一份 146 行的 `.frac.md` 有 79 KB，按“中层目录小于 120 行、根目录小于 150 行”的旧建议，它都不算超。

读的成本、写的成本、上下文里占的位置，都跟字节数走。所以上限用字节（按 UTF-8 计）。

## 为什么预算只看本目录自己

```text
budget(D) = min(10 KiB, 2 KiB + 直属条目数(D) × 340 B)
```

内容多少主要取决于要交代几个直属条目，所以按条目数给。

不和仓库里最大的目录比：要是按“最大的目录给 10 KiB、其余按比例”来算，别的目录多一个文件，所有目录的预算都会跟着动——一个无关的小变量就能让一批文件从“合格”变成“超预算”。只看自己，预算只在自己的条目变了时才变。

## 为什么不写易变数字和版本史

`.frac.md` 是“现在是什么”的地图。版本史、测试条数、行号、日期这类东西有两个问题：

```text
它们只增不减：每轮都往上加一句“这一版加了什么”，从来没有人删
它们一改就错：测试多一条，就要找出所有写着旧条数的 .frac.md 逐个改
```

历史在 git log，数字在代码和测试里。`.frac.md` 只写读者动手前需要知道、而且下一轮大概率还成立的东西。

## 为什么要有 confirm

stale 只说明“输入比它新”，不说明内容错了。没有 `confirm`，让一份 stale 的 `.frac.md` 变回 fresh 的唯一办法是改它的内容——于是每一轮都在每一层追加一句，越写越长。

`confirm` 把“内容还对”和“内容要改”分开：内容还对，只更新时间戳；上层原本是新的，一起确认。

## 为什么 skill 副本不进树、而且自己更新

skill 是从上游 kit 拷进仓库的，不是仓库自己的内容；它的说明就是 SKILL.md。如果它也有 `.frac.md`，kit 每发一版，副本里的文件一变，从 skill 目录到根目录的整条链都会变旧，每个仓库都要为别人的改动重写一遍摘要。所以副本不进树：`*/skills/frac-context/`、`skills/frac-context/`，以及正在运行的那一份，都按忽略处理。

规矩修正了，要让所有仓库都用上，最可靠的是工具自己去取：`frac.py` 是每一轮都会跑的必经之路，在这里查一次版本最便宜。取回来的每个文件都要对上 sha256，任何一步不过就保留旧版；本地改过的不覆盖。换完要提示 Agent 重读 SKILL.md，因为这一轮已经按旧规矩开工了。

## 判断系统是否走偏

如果出现以下现象，说明系统开始膨胀：

```text
任何一份 .frac.md 超过 10 KiB
某份 .frac.md 每次提交都变长、从来没变短过
一条直属文件的说明比一屏还长
.frac.md 里出现版本号、日期、测试条数、提交号
根 .frac.md 超过 300 行
每次修改都触发大面积无意义重写
Agent 更新父级时经常读孙目录
需要人工频繁思考该给模型哪些 token
.frac.md 出现大量空话
引入数据库、embedding、图谱、复杂 schema
```
